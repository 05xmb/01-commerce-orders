# 题目 01 需求说明 — 小型电商的订单交易、发货与售前退款

- 版本：v0.1（2026-11-12 需求分析阶段产出）
- 依据：题目 01 题面 + 题集第一部分共同要求
- 配套：`AGENTS.md` v0.3、`docs/assumptions.md`（假设清单）
- 编号约定：业务规则 R1~R8（对应题面"业务范围与规则"8 条），演示场景 S1~S5（对应题面"必须演示的完整工作场景"5 组），验收点以 `R<n>-T<m>` / `S<n>-T<m>` 编号，供测试用例与任务清单引用。

---

## 1. 业务概述

Shop 商城售卖少量标准商品：运营维护商品售价与可售数量，买家网页下单并在线支付，仓库按已付款订单发货，客服处理取消、退款与支付异常。**一张订单同时影响库存、收款、发货与客服处理**，系统必须保证四者一致且全程可追溯。

## 2. 角色与权限

| 角色 | 预置 | 可执行操作 | 不可执行（越权防线） |
| --- | --- | --- | --- |
| 买家 | buyer01~03 | 浏览在售商品、下单、付款（经模拟渠道）、查询本人订单、取消待付款订单、对已付款未发货订单申请整单退款、查看运单与退款结果 | 看他人订单、发货、审核退款、改库存 |
| 运营 | op01 | 商品上架 / 下架 / 改价、查看可售数量、按订单穿透查询收款 / 退款 / 发货 / 异常记录、交易汇总（已收款 / 已退款） | 发货、审核退款、直接修改订单状态消除异常 |
| 仓库 | wh01 | 查询可发货订单、登记承运方与运单号完成发货（每单一次） | 为已发货 / 退款审核中 / 已退款订单发货、处理退款 |
| 客服 | cs01 | 审核售前退款（同意 / 拒绝 + 原因）、查看并处理异常支付（核实后发起退款）、重试失败的退款 | 直接修改订单状态 / 库存、替买家下单 |
| 模拟支付渠道 | 独立服务 | 受理付款 / 退款，异步发送支付 / 退款通知（成功、失败、超时、重复、异常注入） | — |

身份机制：预置账号 + 简单登录颁发 token；服务端仅从 token 解析身份，禁止信任请求体中的用户编号。

## 3. 预置数据与业务边界

- 商品 2 个：商品 A 单价 10000 分、可售数量 5；商品 B（陪衬，价格 / 库存自定并记录于假设清单）。
- 买家 3 个；每单仅购买一种商品，数量 1~2 件；金额一律人民币分（整数），不含运费与优惠。
- **不做**：购物车、多商户、真实物流、部分退款、完整财务系统、注册登录全套、真实短信、签收与售后退货。

## 4. 核心实体（数据模型草案）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| product | id、名称、单价（分）、可售数量、状态（在售 / 下架）、乐观锁版本 | 可售数量反映占用（见 R1/R2） |
| stock_flow | id、商品 id、订单号、变动类型（下单占用 / 取消释放 / 超时释放 / 退款回补）、数量、变动前后值、时间 | **库存流水表**，一切库存变动留痕对账 |
| order | 订单号、买家 id、商品快照（名称 + 下单时单价）、数量、金额、状态、创建时间、支付截止时间、支付时间、关闭时间、关闭原因、版本 | 快照不随后续改价变化 |
| payment | 渠道交易号（唯一）、订单号、金额、状态、完成时间 | 一笔订单至多一条有效收款 |
| pay_notify_log | 通知编号、订单号、渠道交易号、金额、验签结果、处理结果（成功 / 重复 / 金额不符 / 未知订单 / 验签失败 / 迟到）、原始报文、时间 | 全部通知留痕，含被拒绝者 |
| refund | 退款单号、订单号、金额、类型（售前退款 / 迟到支付退款）、状态（审核中 / 已拒绝 / 退款中 / 已退款 / 退款失败待处理）、买家申请原因、客服处理原因、渠道退款号、时间 | 退款状态独立可查询 |
| refund_notify_log | 同 pay_notify_log 结构 | 退款通知留痕与幂等判定 |
| shipment | 订单号（唯一）、承运方、运单号、发货人、发货时间 | 每单至多一条 |
| exception_payment | 通知编号、订单号、渠道交易号、金额、状态（待处理 / 已退款）、处理人、处理时间、关联退款单号 | 迟到支付的独立台账，不随订单状态消失 |
| user | id、账号、姓名、角色、密码散列 | 预置 |

## 5. 订单状态机与主流程

### 5.1 状态机

```mermaid
stateDiagram-v2
    [*] --> 待付款: 下单(库存占用)
    待付款 --> 待发货: 支付通知验签通过且未超时(记收款)
    待付款 --> 已关闭: 买家取消/超时关单(释放库存,仅一次)
    待发货 --> 退款审核中: 买家申请整单退款(暂停发货)
    退款审核中 --> 待发货: 客服拒绝(记录原因,恢复可发货)
    退款审核中 --> 退款中: 客服同意(请求渠道退款)
    退款中 --> 已退款: 渠道退款成功通知(回补库存,仅一次)
    退款中 --> 退款失败待处理: 渠道明确失败(客服可重试)
    退款失败待处理 --> 退款中: 客服重试
    待发货 --> 已发货: 仓库登记承运方+运单号(仅一次)
    已发货 --> [*]
    已退款 --> [*]
    已关闭 --> [*]
    note right of 已关闭
        关闭后收到成功支付通知:
        订单不回溯,库存不恢复
        → 生成异常支付待处理记录
        → 客服核实发起退款(不回补库存)
    endnote
```

### 5.2 关键流转规则

| # | 流转 | 约束 |
| --- | --- | --- |
| F1 | 下单 | 商品在售且 `可售 ≥ 数量`；事务内条件更新扣可售 + 创建订单 + 写占用流水；失败不超卖 |
| F2 | 支付通知 | 验签 → 匹配订单与金额 → 幂等判定 → 按订单当前状态分流：待付款→收款转待发货；已关闭→记异常支付；其他→记重复 / 冲突 |
| F3 | 关闭（取消 / 超时） | 仅待付款可关；释放占用且库存流水只写一条；重复关闭幂等 |
| F4 | 退款申请 | 仅待发货可申请；申请期间发货接口必须拒绝该订单 |
| F5 | 退款审核 | 客服写原因；拒绝→回待发货；同意→请求渠道退款 |
| F6 | 退款通知 | 验签 + 幂等；售前退款成功回补库存一次；迟到支付退款**不回补**；失败→退款失败待处理 |
| F7 | 发货 | 仅待发货（且无退款审核中标记）可发；每单一次；已发货不受理售前退款 |
| F8 | 超时关单 | 以服务端时间为准；定时扫描 + 读取时惰性检查兜底；演示环境 30s、生产 600s，仅时长参数不同 |

## 6. 业务规则 → 可验证验收条件

| 规则 | 验收点 | 可验证条件（操作 → 预期 → 取证方式） |
| --- | --- | --- |
| R1 下单与快照 | R1-T1 | 对已下架 / 库存不足商品下单 → 返回明确错误，不产生订单与流水 → 接口响应 + 数据库 |
| | R1-T2 | 下单后运营改价 / 下架 → 已创建订单金额与商品快照不变 → 订单详情接口 |
| | R1-T3 | 成功下单后可售数量立即减少对应件数，库存流水出现"下单占用"记录 → 商品接口 + stock_flow |
| R2 关闭与释放 | R2-T1 | 待付款订单超过支付时限 → 被自动关闭（服务端时间），库存释放一次 → 订单状态 + 流水 |
| | R2-T2 | 对同一订单重复取消 / 重复触发超时任务 → 释放流水仅一条，库存不多释放 → 流水计数 |
| | R2-T3 | 已关闭订单可购买库存被其他买家买到 → 新订单成功 → 订单列表 |
| R3 支付通知 | R3-T1 | 重复发送相同成功通知 → 只记一次收款，订单不重复流转 → payment 唯一 + notify_log 标记"重复" |
| | R3-T2 | 用同一渠道交易号匹配另一订单号 → 拒绝并记录 → notify_log |
| | R3-T3 | 金额不符 / 未知订单号 / 错误签名的通知 → 分别拒绝且结果可查询 → notify_log + 查询接口 |
| R4 迟到支付 | R4-T1 | 订单关闭后送达成功通知 → 订单仍关闭、库存不变、异常支付列表 +1 → 订单接口 + exception_payment |
| | R4-T2 | 客服从异常列表发起退款 → 渠道确认成功 → 买家可见退款结果，**库存不回补** → 退款单 + stock_flow 无回补记录 |
| R5 退款审核 | R5-T1 | 退款审核中调用发货接口 → 明确拒绝 → 接口响应 + 无 shipment 记录 |
| | R5-T2 | 客服拒绝退款（填原因）→ 订单回待发货，可正常发货 → 状态 + 发货成功 |
| | R5-T3 | 并发发起退款申请与发货 → 最终只有"已退款未发货"或"已发货无退款"一种结果 → 终态 + 流水一致 |
| R6 退款执行 | R6-T1 | 渠道首次退款失败 → 退款单进入"退款失败待处理"，客服重试后成功 → 状态流转记录 |
| | R6-T2 | 售前退款成功 → 库存回补一次（流水"退款回补"），重复退款通知不重复回补、不重复记退款 → 流水计数 |
| R7 发货 | R7-T1 | 待发货订单登记承运方 + 运单号 → 发货成功；再次发货 → 拒绝 → shipment 唯一 |
| | R7-T2 | 已发货订单申请售前退款 → 明确拒绝 → 接口响应 |
| R8 运营核查 | R8-T1 | 按订单查询可得收款 / 退款 / 发货 / 异常全记录 → 运营接口逐单穿透 |
| | R8-T2 | 运营汇总（可售数量、已收款、已退款）与明细对平 → 汇总接口 vs 明细核算 |
| | R8-T3 | 不存在任何接口可通过修改订单状态消除异常记录 → 尝试后异常台账仍在 |
