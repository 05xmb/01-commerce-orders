# 原型设计说明（题目 01）

- 版本：v0.1（2026-11-12 原型设计阶段产出）
- 原型文件：`prototype/index.html`（单文件、浏览器直接打开、可点击；内存态演示数据，刷新还原）
- 配套：`docs/requirements.md`（验收点编号 R/S-T）、`docs/assumptions.md`

## 1. 原型定位与边界

- 目的：在开发前验证**页面划分、角色操作路径、正常结果与异常状态的展示方式**，不是最终 UI。
- 正式实现为 Vue3 + Element Plus SPA（Nginx 托管）；原型中的交互逻辑（如下单扣库存、退款审核）在正式版全部由后端接口完成，原型仅演示"页面长什么样、操作后出现什么状态"。

| 页面 | 角色 | 主要操作 | 覆盖题面要求 |

| 模拟支付弹窗 | 买家 × 渠道 | 模拟支付成功 / 失败 / 补发重复通知（按钮只操作渠道，状态由通知驱动） | R3、A6、A14 |
| 仓库 · 待发货工作台 | 仓库 | 登记承运方 + 运单号发货；退款审核中订单发货按钮禁用并提示 | R5、R7 |
| 客服 · 退款审核 | 客服 | 同意 / 拒绝（必填原因）；同意后请求渠道退款 | R5 |

## 3. 用原型可直接演示的状态与异常

| 演示动作 | 原型中的表现 | 对应验收点 |
| --- | --- | --- |
| 商品 A 下单 | 可售 5→4，库存流水新增"下单占用"，订单进"待付款"并倒计时 | R1-T3 |
| 取消订单 | 状态→已关闭，库存回补一次；再点取消提示"重复关闭不重复释放" | R2-T2 |
| 支付成功 | 订单→待发货，通知日志记"成功"；已收款合计增加 | R3-T1、S1 |
| 补发重复通知 | 日志记"重复：幂等拦截"，金额不变 | R3-T1 |
| 申请退款后切到仓库页 | 该订单发货按钮禁用，提示"退款审核中，暂停发货" | R5-T1 |
| 客服同意退款 | 先进入"退款中"，随后演示渠道首次失败→"退款失败待处理" | R6-T1、S3 |
| 客服重试退款 | →已退款，库存流水新增"退款回补"，订单终态 | R6-T2、S3 |
| 买家对已关闭订单点"模拟渠道迟到通知" | 订单不变、库存不变，异常支付列表 +1 | R4-T1、S4 |
| 客服处理异常支付 | →已退款，提示"不回补库存"，可售数量不变 | R4-T2、S4 |
| 运营改价 / 下架 | 商品卡片变化，历史订单仍显示快照价 | R1-T2 |

## 4. 正式实现时的页面差异说明

- 倒计时：原型为静态展示；正式版由后端返回支付截止时间，前端倒计时仅展示，超时判定以服务端为准（A5）。
- 并发抢购（S2）：原型无法演示真实并发；正式版用可重复执行的并发测试 / 脚本演示（A12）。
- 迟到通知：原型用按钮直接模拟；正式版由渠道端延迟推送实现（A14）。
- 退款"首次失败"：原型为固定编排；正式版由模拟渠道对首次退款请求返回失败、重试返回成功（S3 场景要求）。
